= Guardrails Evaluation

Accuracy and performance do not answer *“is this safe to serve?”* This module evaluates content-safety guardrails on Korean hate-speech data: compare regex-only filtering against model-backed safety, then measure precision, recall, and F1 on the K-MHaS dataset.

== Learning Objectives

* Contrast regex-only vs content-safety guardrail behaviour
* Run a structured evaluation notebook against K-MHaS samples
* Interpret confusion-matrix style metrics and HTML reports

== How This Fits the Workshop

EvalHub Modules 3–5 focus on Hub-orchestrated jobs and MLflow experiments. Guardrails evaluation uses the lab’s NeMo Guardrails / Kanana notebooks to add a *safety gate*. Together they form a practical release checklist: *accurate*, *fast enough*, and *safe enough*.

== Key Concept: Safety Metrics Beyond “Blocked or Not”

The evaluation notebooks compute classification metrics on labeled hate vs not-hate samples. Conceptually you care about:

[cols="1,2",options="header"]
|===
| Metric | Interpretation

| *Precision*
| Of blocked items, how many were truly harmful (lower false positives)

| *Recall*
| Of harmful items, how many were blocked (lower false negatives)

| *F1 / Accuracy*
| Overall balance for the operating point you chose
|===

[NOTE]
====
Higher recall usually means fewer missed hate-speech cases but can increase over-blocking (false positives). Product policy decides which error type is more expensive.
====
