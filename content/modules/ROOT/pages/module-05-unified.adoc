= Unified Evaluation in One Experiment

In this module, you will bring accuracy and performance together. You will run five Korean accuracy benchmarks and a GuideLLM throughput test against your model, record all of their results in a single MLflow experiment, and compare them side by side.

By the end of this module, you will have:

* An understanding of why release decisions need accuracy and performance results for the same model version
* Five accuracy jobs and one performance job recorded under one MLflow experiment
* A comparison of all results in the notebook and in MLflow

== Why a Unified Evaluation?

In Modules 3 and 4, each job created its own experiment. That works for exploring one dimension at a time, but a release decision needs every dimension for the same model version, side by side:

* *Is the new version accurate enough?* Accuracy on each benchmark must meet your threshold.
* *Is it fast enough?* Throughput and latency must meet your service-level objectives.
* *Is it better than the previous version?* You need the same set of results for every version, so that you can compare them.

Recording one evaluation round in one MLflow experiment gives you that record. When you evaluate the next model version with the same benchmarks and settings, you can compare the two rounds directly.

== How the Unified Evaluation Works

The notebook runs the evaluation in two phases and records both in an experiment named `<model-name>-full-eval-<timestamp>`:

[cols="1,2,3",options="header"]
|===
| Phase | Jobs | What happens

| *Phase A: Accuracy*
| 5 Korean MCQ jobs: `click`, `haerae`, `kmmlu`, `kmmlu_hard`, and `kobest_boolq`
| All five jobs are submitted at once and run in parallel, each on `LIMIT` questions.

| *Phase B: Performance*
| 1 GuideLLM job with the `throughput` profile
| Starts after all accuracy jobs finish, so that the accuracy jobs do not add load to the model during the performance test. It sends requests as fast as the model accepts them, for up to 180 seconds or 50 requests, to measure maximum throughput.
|===

As you saw in Module 3, GuideLLM jobs do not log their metrics to MLflow themselves. The notebook therefore includes a step that logs the GuideLLM metrics to the same experiment, so that all results appear in one place.

== Key Concept: One Experiment, Many Jobs

Every job in the unified evaluation uses the same `ExperimentConfig` name. The jobs can use different providers, but MLflow groups all of their runs under one experiment:

[source,python,subs=none]
----
EXPERIMENT_NAME = f"{MODEL_NAME}-full-eval-{ts}"

# Phase A: one accuracy job per benchmark, all in the same experiment
for bm in ["click", "haerae", "kmmlu", "kmmlu_hard", "kobest_boolq"]:
    client.jobs.submit(JobSubmissionRequest(
        name=f"unified-{bm}-{ts}",
        model=model,
        benchmarks=[BenchmarkConfig(
            id=bm,
            provider_id=KOREAN_PROVIDER_ID,
            parameters={"temperature": 0.0, "max_tokens": 1024, "limit": LIMIT},
        )],
        experiment=ExperimentConfig(name=EXPERIMENT_NAME),
    ))

# Phase B: a performance job in the same experiment
perf_request = JobSubmissionRequest(
    name=f"unified-perf-{MODEL_NAME}-{ts}",
    model=guidellm_model,
    benchmarks=[BenchmarkConfig(
        id="throughput",
        provider_id="guidellm",
        parameters={
            "profile": "throughput",
            "max_seconds": 180,
            "max_requests": 50,
            "data": "prompt_tokens=128,output_tokens=64",
            "request_type": "chat_completions",
        },
    )],
    experiment=ExperimentConfig(name=EXPERIMENT_NAME),
)
----

A single job can also contain several benchmarks in its `benchmarks` list. The notebook shows this pattern in *Evaluation 1*, but the unified evaluation submits one job per benchmark so that you can follow each benchmark's progress separately.

Before you start, make sure you have completed Modules 2 to 4. This module uses the same `.env` file, the `oc` login from Step 2.5 of Module 2, and the Korean MCQ provider registered in Module 2.

*Notebook path:* `{evalhub-lab-clone}/3_eval_hub_unified_benchmark/1_unified_benchmark.ipynb` ({evalhub-lab-repo}/blob/main/3_eval_hub_unified_benchmark/1_unified_benchmark.ipynb[view on GitHub,window=_blank])

. Run the cells one at a time from the top by selecting each cell and pressing *Shift+Enter*.

NOTE: The number of questions per benchmark comes from `LIMIT` in `.env` and defaults to `5`. If you changed `.env` since Module 4, restart the notebook kernel (*Kernel* > *Restart Kernel*) before running the first cell.

== Step 5.3: View the Unified Experiment in MLflow

. In the {productname-short} dashboard, expand *Develop & train* in the left navigation and click *Experiments*.
. Select your project from the *Project* drop-down.
. Click the experiment named `<model-name>-full-eval-<timestamp>` that the notebook printed.
. At the top of the experiment page, switch the view from *GenAI* to *Model training*. The experiment contains the runs of all six jobs:
+
* For each accuracy job, a run named `unified-<benchmark>-<timestamp>` that EvalHub creates when the job is submitted, and a run named after the job ID with the suffix `_0` that contains the accuracy metrics.
* For the GuideLLM job, a run named `unified-perf-<model-name>-<timestamp>` with the evaluation card, and a run named `guidellm-unified-perf-...` that contains the performance metrics logged by the notebook.
+
image::unified/img-unified-mlflow-model-training-runs.png[Model training view of the full-eval experiment listing the runs of the five accuracy jobs and the GuideLLM job]
+
The runs named after a job ID, which show a completed status and a short duration, are the accuracy runs that contain metrics. The `unified-...` runs remain in the *Running* state.

. To compare the results, click the chart icon above the run list. MLflow shows one chart per metric, with one bar per run in a different color:
+
* `overall_accuracy` and `overall_score` compare the five benchmarks at a glance.
* The `category_accuracy.<category>` charts show the accuracy for each category that the sampled questions came from.
* The GuideLLM throughput and latency metrics appear as additional charts once the notebook has logged them.
+
Click the eye icon next to a run in the list to hide it from or show it in the charts.
+
image::unified/img-unified-mlflow-charts.png[Chart view of the full-eval experiment comparing category accuracy, overall accuracy, and overall score across the accuracy runs]

TIP: When you evaluate another model or a new version later, keep the benchmark IDs, `LIMIT`, and GuideLLM profile the same. MLflow comparisons are only meaningful when the evaluation settings match.
