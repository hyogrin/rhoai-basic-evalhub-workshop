= Korean MCQ Accuracy Benchmark

In this module, you will measure how accurately your model answers Korean multiple-choice questions. You will submit an accuracy job to the Korean MCQ provider that you registered in Module 2, review the per-category results in MLflow, and generate a summary report.

By the end of this module, you will have:

* An understanding of the Korean benchmarks available in this workshop and how they score a model
* A HAE-RAE accuracy job run through EvalHub, with its results recorded in MLflow
* Your evaluation results exported to the lab repository and summarized in a Markdown and HTML report

== Why Korean Benchmarks?

General-purpose benchmarks are mostly written in English. A model that performs well on them can still struggle with Korean vocabulary, grammar, history, law, or culture. If your users interact in Korean, you need benchmarks written in Korean to know whether the model is fit for them.

Multiple-choice questions (MCQ) make this measurable: each question has one correct answer, so accuracy can be scored automatically and compared across models, versions, and serving configurations.

== How the Korean MCQ Evaluator Scores a Model

For each benchmark job, EvalHub starts the Korean MCQ adapter image you built in Module 2 as a pod in your namespace. The adapter:

. Downloads the benchmark dataset from Hugging Face.
. Formats each question and its choices as a prompt and sends the prompts to your model endpoint in parallel.
. Parses the chosen answer from each response and compares it with the correct answer.
. Reports the results to EvalHub and logs them to MLflow:
** `overall_accuracy` -- the percentage of questions answered correctly
** `category_accuracy.<category>` -- the accuracy for each category in the benchmark
** `overall_score` -- the overall accuracy as a value between 0 and 1

The `limit` parameter sets how many questions are evaluated. The workshop uses a small limit so that jobs finish in class time. A full benchmark run evaluates thousands of questions and belongs in a longer offline evaluation.

== Key Concept: Same Job API, Different Provider

Accuracy jobs use the same client and `JobSubmissionRequest` structure as the GuideLLM jobs in Module 3. Only the provider, benchmark ID, and parameters change:

[source,python,subs=none]
----
single_request = JobSubmissionRequest(
    name="haerae-eval",
    description="HAE-RAE benchmark - Korean language understanding",
    tags=["korean", "haerae", MODEL_NAME],
    model=model,
    benchmarks=[
        BenchmarkConfig(
            id="haerae",                       # benchmark in the Korean MCQ provider
            provider_id=KOREAN_PROVIDER_ID,    # discovered with client.providers.list()
            parameters={"temperature": 0.0, "max_tokens": 1024, "limit": LIMIT},
        ),
    ],
    experiment=ExperimentConfig(
        name="korean-haerae-eval",
        tags=[
            ExperimentTag(key="language", value="korean"),
            ExperimentTag(key="benchmark_suite", value="haerae"),
        ],
    ),
)

job = client.jobs.submit(single_request)
----

Setting `temperature` to `0.0` makes the model's answers as deterministic as possible, so repeated runs on the same questions give comparable accuracy.

== Step 4.3: View the Accuracy Results in MLflow

Unlike the GuideLLM jobs in Module 3, the Korean MCQ adapter logs its metrics directly to MLflow, so you can view them as charts.

. In the {productname-short} dashboard, expand *Develop & train* in the left navigation and click *Experiments*.
. Select your project from the *Project* drop-down.
. Click the `korean-haerae-eval` experiment. It appears at the top of the list, above the GuideLLM experiments from Module 3 and the `korean-llm-evaluation` experiment from Module 2.
+
image::kmcq/img-kmcq-mlflow-experiments-list.png[Experiments page listing the korean-haerae-eval experiment above the GuideLLM and korean-llm-evaluation experiments]

. At the top of the experiment page, switch the view from *GenAI* to *Model training*. The experiment contains two runs:
+
* `haerae-eval`, which EvalHub creates when the job is submitted. It stays in the *Running* state and has no metrics.
* A run named after the job ID with the suffix `_0`, for example `8eb3ae4e-..._0`. The Korean MCQ adapter creates this run and logs the accuracy metrics to it.
+
image::kmcq/img-kmcq-mlflow-model-training-runs.png[Model training view of the korean-haerae-eval experiment listing the haerae-eval run and the job ID run]

. Click the run named after the job ID, then open the *Model metrics* tab. MLflow shows one chart per metric: `overall_accuracy`, `overall_score`, and the `category_accuracy` of each HAE-RAE category in the sample.
+
image::kmcq/img-kmcq-mlflow-model-metrics.png[Model metrics tab of the HAE-RAE run showing charts for category accuracy, overall accuracy, and overall score]

With a small `LIMIT`, only one or a few categories contain questions, and each accuracy value is based on very few answers. For example, 5 correct answers out of 5 produce an `overall_accuracy` of `100`. Treat these results as a check that the pipeline works, not as a reliable measure of the model's Korean ability.

The `results` folder already contains sample results for several other models, such as `glm-53-flash`, `gemma4-12b`, and `qwen3-14b`, from earlier evaluations by the lab authors.
