= GuideLLM Performance Benchmark

Accuracy alone does not make a model production-ready. This module measures *inference performance* -- TTFT, inter-token latency, throughput, and end-to-end latency -- using *GuideLLM* through the EvalHub SDK so results land in MLflow like any other evaluation job.

== Learning Objectives

* Submit a GuideLLM job via `JobSubmissionRequest`
* Understand constant / sweep style profiles at a high level
* Locate performance metrics in the corresponding MLflow experiment

== Key Concept: One Client, One Job Shape

EvalHub treats GuideLLM as a *provider*. You still use the same client and job submission types as accuracy benchmarks:

[source,python,subs=none]
----
from evalhub import (
    SyncEvalHubClient,
    BenchmarkConfig,
    JobSubmissionRequest,
    ExperimentConfig,
)

client = SyncEvalHubClient(
    base_url=EVALHUB_URL,
    auth_token=EVALHUB_AUTH_TOKEN,
    insecure=True,
    tenant=NAMESPACE,
)

quick_request = JobSubmissionRequest(
    name=f"guidellm-quick-{MODEL_NAME}",
    description=f"Quick performance baseline for {MODEL_NAME}",
    tags=["performance", "guidellm", MODEL_NAME],
    model=model,  # ModelConfig from lab helpers
    benchmarks=[
        BenchmarkConfig(
            id="constant",
            provider_id="guidellm",
            parameters={
                "profile": "constant",
                "rate": 2,
                "max_seconds": 120,
                "data": "prompt_tokens=256,output_tokens=128",
                "request_type": "chat_completions",
            },
        )
    ],
    experiment=ExperimentConfig(name=f"guidellm-quick-{MODEL_NAME}"),
)

job = client.jobs.submit(quick_request)
print(job.id, job.state.value)
----

The notebook also walks through sweep and constant-load variants. You do not need to retype them here -- run the notebook cells and watch job state until completion.

== Verify in MLflow

. Open *Experiments* in the {productname-short} / MLflow UI.
. Select the experiment name created by the job (for example `guidellm-quick-...` or the name printed by the notebook).
. Inspect logged metrics such as output tokens/sec, request rate, and latency percentiles.

[NOTE]
====
Exact metric names depend on the GuideLLM profile and EvalHub version. Use the notebook’s printed summary plus the MLflow run page as the source of truth.
====
