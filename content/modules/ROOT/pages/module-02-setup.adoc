= Setup EvalHub and MLflow

[#setup]
In this module you prepare the workbench, configure the model, EvalHub, and MLflow connections in `.env`, and verify connectivity with the setup notebook. EvalHub and MLflow must already be deployed, with access to your assigned project configured by your instructor.

== Learning Objectives

* Clone the EvalHub lab into your workbench
* Collect the connection settings in Web Terminal and apply them to `.env` together
* Verify EvalHub API reachability with the Python SDK

=== Step 2.1: Collect and Apply the Environment

==== A. Web Terminal: Generate Your `.env` Settings

In this step, a small script asks you four questions about your model. It then finds the EvalHub and MLflow connection details for you and prints seven settings, ready to copy. It only reads cluster information and changes nothing.

*Before you start, have these four values ready* (your instructor or the model's details page in the {productname-short} dashboard provides them):

[cols="1,2,2",options="header"]
|===
| Prompt | What to enter | Example

| *Namespace*
| Your assigned user namespace
| `user1`

| *Model ID*
| The model's API ID (not its display name)
| `redhataigemma-4-e4b-it`

| *Model API base URL*
| The model endpoint, ending in `/v1`
| `\https://maas.{openshift_cluster_ingress_domain}/user1/redhataigemma-4-e4b-it/v1`

| *Model API key*
| The API key for that endpoint
| `sk-oai-****************`
|===

*1. Open the Web Terminal*

In the OpenShift console, click the *`>_`* (terminal) icon at the top right. A terminal opens at the bottom of the page. It starts in the `openshift-terminal` project; that is expected and does not need to match your namespace.

image::setup/img-open-web-terminal.png[OpenShift console header with the Web Terminal icon highlighted]

*2. Run the setup script*

Copy the command below, paste it into the Web Terminal, and press *Enter*:

[source,bash,role="execute"]
----
(
    set -o pipefail
    curl -fsSL https://raw.githubusercontent.com/hyogrin/rhoai-basic-evalhub-workshop/refs/heads/main/scripts/setup-env.sh | bash
)
----

You can review the https://github.com/hyogrin/rhoai-basic-evalhub-workshop/blob/main/scripts/setup-env.sh[setup script source,window=_blank] before running it.

*3. Answer the four prompts*

Type each value and press *Enter*. A completed session looks like this:

[source,text,subs="attributes+"]
----
Assigned namespace (user1, user2, user3, ...): user1
Served model ID: redhataigemma-4-e4b-it
Model API base URL (including /v1 when required): https://maas.{openshift_cluster_ingress_domain}/user1/redhataigemma-4-e4b-it/v1
Model API key (Enter only for an unauthenticated endpoint):
----

[NOTE]
====
The API key is *hidden while you type or paste it*, so nothing appears on screen. This is normal. Paste the key once and press *Enter*.
====

Avoid these common mistakes:

[cols="1,2,2",options="header"]
|===
| Prompt | Correct | Incorrect

| Namespace
| `user1`
| `openshift-terminal` or `redhat-ods-applications`

| Model ID
| `redhataigemma-4-e4b-it`
| `RedHatAI/gemma-4-E4B-it` (the display name)

| Model API base URL
| `.../redhataigemma-4-e4b-it/v1`
| `.../v1/chat/completions` or a `localhost` URL

| Model API key
| `sk-oai-****************`
| `Bearer sk-oai-****************`
|===

*4. Copy the output*

The script prints a block between `# BEGIN .env` and `# END .env`. For example:

[source,dotenv,subs="attributes+"]
----
# BEGIN .env - copy from NAMESPACE through MLFLOW_TRACKING_URI
NAMESPACE='user1'
MODEL_NAME='redhataigemma-4-e4b-it'
MODEL_ENDPOINT='https://maas.{openshift_cluster_ingress_domain}/user1/redhataigemma-4-e4b-it/v1'
MODEL_API_KEY='sk-oai-****************'
EVALHUB_URL='https://evalhub-redhat-ods-applications.{openshift_cluster_ingress_domain}'
EVALHUB_AUTH_TOKEN='sha256~****************'
MLFLOW_TRACKING_URI='https://mlflow.redhat-ods-applications.svc:8443/mlflow'
# END .env
----

image::setup/img-set-env-in-terminal.png[Web Terminal showing the four answered prompts and the generated .env block]

*Select and copy the seven lines from `NAMESPACE=` through `MLFLOW_TRACKING_URI=`.* You paste them into the Workbench in the next step. Your values will differ from the example; always use your own output.

.Troubleshooting and details (click to expand)
[%collapsible]
====
* *`Forbidden`, missing resource, or missing service port:* ask your instructor to check your access and the service names. The script stops without printing the block when a lookup fails.
* *HTTP `401` later in the notebooks:* your OpenShift token has expired. Rerun the script, then replace the contents of `.env` with the new output.
* *HTTP `403`:* your user may lack permissions in the namespace. Ask your instructor.
* *Where the services run:* EvalHub and MLflow are shared services in `redhat-ods-applications`. The script looks for the `evalhub` resource and the `mlflow` HTTPS service (port `8443`) there. Your `NAMESPACE` stays as your own user namespace.
* *Services in a different namespace:* if your instructor deployed them elsewhere, run `export EVALHUB_NAMESPACE=<namespace>` or `export MLFLOW_NAMESPACE=<namespace>` before the script.
* *URL format:* `EVALHUB_URL` can be an internal service URL or a route; both work from the Workbench. It must not end in `/api/v1`. Keep any path such as `/mlflow` in `MLFLOW_TRACKING_URI`.
* *Why the parentheses and `pipefail`:* they make the command fail cleanly if the download fails, without changing your terminal's settings.
====

. If `.env` already contains text, press `Esc` and type `ggdG` to clear its contents.

[IMPORTANT]
====
Copy the printed values, including the actual `EVALHUB_AUTH_TOKEN`. The notebooks read `.env` with `python-dotenv`; they do not execute shell commands in it. You do not need to run `source .env` or manually run `oc` in the Workbench terminal for this configuration step.

The generated block contains credentials. Keep it in `.env` and do not commit it to Git.
====

The instructor must provision EvalHub, the project's MLflow workspace and artifact storage, and the required notebook identity permissions. The current lab notebooks can still invoke `oc` internally for cluster setup and model Secret management; copying `EVALHUB_AUTH_TOKEN` authenticates SDK requests and does not establish a Workbench CLI login. When a model key is set, the notebook identity needs permission to manage the `model-api-key` Secret in your assigned namespace.

=== Step 2.2: What the Notebook Configures

The participant cells load the saved configuration and check that EvalHub responds. The example below requires the namespace and token collected in Web Terminal:

[source,python,subs=none]
----
import os
from dotenv import load_dotenv
from evalhub import SyncEvalHubClient

load_dotenv(dotenv_path="../.env", override=True)

EVALHUB_URL = os.getenv("EVALHUB_URL")
EVALHUB_AUTH_TOKEN = os.getenv("EVALHUB_AUTH_TOKEN")
NAMESPACE = os.getenv("NAMESPACE", "").strip()

if not NAMESPACE:
    raise ValueError(
        "Set NAMESPACE in ../.env to your assigned namespace (user1, user2, user3, ...)."
    )

if not EVALHUB_URL or not EVALHUB_AUTH_TOKEN:
    raise ValueError(
        "Paste the complete configuration generated in Web Terminal into ../.env."
    )

client = SyncEvalHubClient(
    base_url=EVALHUB_URL,
    auth_token=EVALHUB_AUTH_TOKEN,
    insecure=True,
    tenant=NAMESPACE,
)

# Connectivity check -- list providers / health as the notebook does
providers = client.providers.list()
print(f"Providers available: {len(providers)}")
----
