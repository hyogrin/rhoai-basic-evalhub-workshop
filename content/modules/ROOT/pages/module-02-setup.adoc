=== Step 2.1: Collect and Apply the Environment

==== A. Web Terminal: Generate the Complete `.env` Block

Open the *Web Terminal* from the terminal icon in the OpenShift console. Run *all `oc` commands in this module in Web Terminal*. Use the Workbench terminal later only to clone the lab and install Python dependencies.

Run the single block below in Web Terminal. It prompts for four values:

* Your assigned lab namespace: `user1`, `user2`, `user3`, and so on. Use your actual assigned namespace, regardless of Web Terminal's current project (`openshift-terminal`).
* The exact served `MODEL_NAME`, from the deployed model details or MaaS model catalog. The display name may differ from the API's model ID.
* The OpenAI-compatible `MODEL_ENDPOINT`, from the model details or MaaS connection information. Keep the routing path and supplied `/v1` suffix; omit `/chat/completions` and do not use `localhost`.
* The `MODEL_API_KEY` issued for that endpoint, without the `Bearer ` prefix. Input is hidden. Press Enter to leave it empty only if the endpoint allows unauthenticated requests.

The script retrieves *EvalHub URL, your current OpenShift token, and MLflow tracking URI together*, then prints all seven `.env` variables. It reads cluster resources and does not change them.

This lab uses an EvalHub resource/service named `evalhub` in your assigned namespace, and a shared HTTPS MLflow service named `mlflow` in `redhat-ods-applications` on port `8443`. If your instructor uses a shared EvalHub or another MLflow namespace, update `EVALHUB_NAMESPACE` or `MLFLOW_NAMESPACE` in the block before running it.

[source,bash,role="execute"]
----
bash <<'SETUP'
set -euo pipefail

fail() {
    printf 'ERROR: %s\n' "$1" >&2
    exit 1
}

# Web Terminal is already authenticated as your OpenShift user.
EVALHUB_AUTH_TOKEN=$(oc whoami -t)
[[ -n "$EVALHUB_AUTH_TOKEN" ]] || fail "No OpenShift token is available. Reopen Web Terminal after signing in."

read -r -p "Assigned namespace (user1, user2, user3, ...): " NAMESPACE </dev/tty
read -r -p "Served model ID: " MODEL_NAME </dev/tty
read -r -p "Model API base URL (including /v1 when required): " MODEL_ENDPOINT </dev/tty
read -r -s -p "Model API key (Enter only for an unauthenticated endpoint): " MODEL_API_KEY </dev/tty
printf '\n' >/dev/tty

[[ -n "$NAMESPACE" && -n "$MODEL_NAME" && -n "$MODEL_ENDPOINT" ]] \
    || fail "Namespace, model ID, and model endpoint are required."

EVALHUB_NAMESPACE="$NAMESPACE"
MLFLOW_NAMESPACE=redhat-ods-applications

# Prefer the named EvalHub route, preserving its scheme and base path.
EVALHUB_URL=$(oc get route evalhub -n "$EVALHUB_NAMESPACE" \
    -o go-template='{{if eq .spec.to.name "evalhub"}}{{if .spec.tls}}https{{else}}http{{end}}://{{.spec.host}}{{with .spec.path}}{{.}}{{end}}{{end}}' \
    2>/dev/null || true)

# A Workbench in the same cluster can also use the internal HTTPS service.
if [[ -z "$EVALHUB_URL" ]]; then
    EVALHUB_PORT=$(oc get svc evalhub -n "$EVALHUB_NAMESPACE" \
        -o jsonpath='{.spec.ports[?(@.port==8443)].port}')
    [[ -n "$EVALHUB_PORT" ]] || fail "The expected EvalHub HTTPS service port 8443 was not found."
    EVALHUB_URL="https://evalhub.${EVALHUB_NAMESPACE}.svc.cluster.local:${EVALHUB_PORT}"
fi

# Read the tracking URI explicitly configured on EvalHub, when present.
MLFLOW_TRACKING_URI=$(oc get evalhub evalhub -n "$EVALHUB_NAMESPACE" \
    -o jsonpath='{.spec.env[?(@.name=="MLFLOW_TRACKING_URI")].value}' \
    2>/dev/null || true)

# Otherwise, verify and use this lab's shared HTTPS MLflow service.
if [[ -z "$MLFLOW_TRACKING_URI" ]]; then
    MLFLOW_PORT=$(oc get svc mlflow -n "$MLFLOW_NAMESPACE" \
        -o jsonpath='{.spec.ports[?(@.port==8443)].port}')
    [[ -n "$MLFLOW_PORT" ]] || fail "The expected MLflow HTTPS service port 8443 was not found."
    MLFLOW_TRACKING_URI="https://mlflow.${MLFLOW_NAMESPACE}.svc:${MLFLOW_PORT}"
fi

# Expand a short MLflow service hostname relative to EvalHub's namespace.
case "$MLFLOW_TRACKING_URI" in
    http://mlflow:*|https://mlflow:*)
        MLFLOW_SCHEME="${MLFLOW_TRACKING_URI%%://*}"
        MLFLOW_ADDRESS="${MLFLOW_TRACKING_URI#*://mlflow:}"
        MLFLOW_TRACKING_URI="${MLFLOW_SCHEME}://mlflow.${EVALHUB_NAMESPACE}.svc:${MLFLOW_ADDRESS}"
        ;;
esac

# Single quotes preserve spaces and # characters when python-dotenv reads values.
print_env() {
    local value="$2"
    local escaped_backslash='\\'
    local escaped_quote="\\'"
    value="${value//\\/$escaped_backslash}"
    value="${value//\'/$escaped_quote}"
    printf "%s='%s'\n" "$1" "$value"
}

printf '\n# BEGIN .env - copy from NAMESPACE through MLFLOW_TRACKING_URI\n'
for key in NAMESPACE MODEL_NAME MODEL_ENDPOINT MODEL_API_KEY \
    EVALHUB_URL EVALHUB_AUTH_TOKEN MLFLOW_TRACKING_URI; do
    print_env "$key" "${!key}"
done
printf '# END .env\n'
SETUP
----

The output contains your assigned namespace, three model settings, and three discovered connection settings, with literal values ready to paste. For example:

[source,dotenv]
----
NAMESPACE='user1'
MODEL_NAME='your-served-model-id'
MODEL_ENDPOINT='https://your-model-endpoint.example.com/v1'
MODEL_API_KEY='your-model-api-key'
EVALHUB_URL='https://evalhub-user1.apps.your-cluster.example.com'
EVALHUB_AUTH_TOKEN='your-current-openshift-token'
MLFLOW_TRACKING_URI='https://mlflow.redhat-ods-applications.svc:8443'
----

Use your actual generated output. EvalHub may use an internal service URL instead of a route; both are valid when reachable from the Workbench. The EvalHub URL must not end in `/api/v1`. Keep any path such as `/mlflow` in the discovered MLflow URI.

If the script reports `Forbidden`, a missing resource, or a missing service port, ask your instructor to verify access and the deployment names. It stops before printing a complete `.env` block when a required lookup fails. If the token later expires or access returns HTTP `401`, rerun this same block in Web Terminal and replace the saved configuration. HTTP `403` can indicate insufficient tenant permissions.

=== Step 2.2: What the Notebook Configures

The participant cells load the saved configuration and check that EvalHub responds. The example below requires the namespace and token collected in Web Terminal:

[source,python,subs=none]
----
import os
from dotenv import load_dotenv
from evalhub import SyncEvalHubClient

load_dotenv(dotenv_path="../.env", override=True)

EVALHUB_URL = os.getenv("EVALHUB_URL")
EVALHUB_AUTH_TOKEN = os.getenv("EVALHUB_AUTH_TOKEN")
NAMESPACE = os.getenv("NAMESPACE", "").strip()

if not NAMESPACE:
    raise ValueError(
        "Set NAMESPACE in ../.env to your assigned namespace (user1, user2, user3, ...)."
    )

if not EVALHUB_URL or not EVALHUB_AUTH_TOKEN:
    raise ValueError(
        "Paste the complete configuration generated in Web Terminal into ../.env."
    )

client = SyncEvalHubClient(
    base_url=EVALHUB_URL,
    auth_token=EVALHUB_AUTH_TOKEN,
    insecure=True,
    tenant=NAMESPACE,
)

# Connectivity check -- list providers / health as the notebook does
providers = client.providers.list()
print(f"Providers available: {len(providers)}")
----
