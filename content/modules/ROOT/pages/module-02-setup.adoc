[#setup]
= Set Up EvalHub and MLflow

In this module, you will connect your workbench to the shared EvalHub and MLflow services and to the model you will evaluate. You will generate your connection settings in the {ocp-short} Web Terminal, save them in the lab repository on your workbench, and then run the setup notebook to confirm that everything works end to end.

By the end of this module, you will have:

* A `.env` file containing your model, EvalHub, and MLflow connection settings
* The lab repository cloned into your workbench, with `oc` logged in as your user
* A verified EvalHub connection and a first evaluation run recorded in MLflow

[NOTE]
====
Your instructor has already deployed EvalHub, MLflow, and the model, and has enabled your namespace for EvalHub jobs. You do not need to deploy or configure any cluster services in this module.
====

== Step 2.1: Generate Your Connection Settings

A setup script asks you four questions about your model, discovers the EvalHub and MLflow connection details for you, and prints seven settings ready to copy. The script only reads cluster information; it does not change anything.

Have these four values ready before you start. Your instructor provides them, or you can find them on the model's details page in the {productname-short} dashboard.

[cols="1,2,2",options="header"]
|===
| Prompt | What to enter | Example

| *Namespace*
| Your assigned user namespace
| `user1`

| *Model ID*
| The model's API ID, not its display name
| `redhataigemma-4-e4b-it`

| *Model API base URL*
| The model endpoint, ending in `/v1`
| `\https://maas.{openshift_cluster_ingress_domain}/user1/redhataigemma-4-e4b-it/v1`

| *Model API key*
| The API key issued for that endpoint
| `sk-oai-****************`
|===

. In the {ocp-short} console, click the *>_* icon in the top-right masthead. The Web Terminal opens at the bottom of the page.
+
image::setup/img-open-web-terminal.png[OpenShift console masthead with the Web Terminal icon highlighted]
+
The terminal starts in the `openshift-terminal` project. This is expected; it does not need to match your namespace.

. Run the setup script:
+
[source,bash,role="execute"]
----
(
    set -o pipefail
    curl -fsSL https://raw.githubusercontent.com/hyogrin/rhoai-basic-evalhub-workshop/refs/heads/main/scripts/setup-env.sh | bash
)
----
+
You can review the https://github.com/hyogrin/rhoai-basic-evalhub-workshop/blob/main/scripts/setup-env.sh[setup script source,window=_blank] before running it.

. Answer the four prompts, pressing *Enter* after each one. A completed session looks like this:
+
[source,text,subs="attributes+"]
----
Assigned namespace (user1, user2, user3, ...): user1
Served model ID: redhataigemma-4-e4b-it
Model API base URL (including /v1 when required): https://maas.{openshift_cluster_ingress_domain}/user1/redhataigemma-4-e4b-it/v1
Model API key (Enter only for an unauthenticated endpoint):
----
+
NOTE: The API key is hidden while you type or paste it, so nothing appears on screen. Paste the key once and press *Enter*.

. Copy the output. The script prints a block between `# BEGIN .env` and `# END .env`:
+
[source,dotenv,subs="attributes+"]
----

NAMESPACE='user1'
MODEL_NAME='redhataigemma-4-e4b-it'
MODEL_ENDPOINT='https://maas.{openshift_cluster_ingress_domain}/user1/redhataigemma-4-e4b-it/v1'
MODEL_API_KEY='sk-oai-****************'
EVALHUB_URL='https://evalhub-redhat-ods-applications.{openshift_cluster_ingress_domain}'
EVALHUB_AUTH_TOKEN='sha256~****************'
MLFLOW_TRACKING_URI='https://mlflow.redhat-ods-applications.svc:8443/mlflow'
# END .env
----
+
.Completed prompts and the generated block in the Web Terminal
image::setup/img-set-env-in-terminal.png[Web Terminal showing the four answered prompts and the generated .env block]
+
Select the seven lines from `NAMESPACE=` through `MLFLOW_TRACKING_URI=` and copy them. You will paste them into your workbench in Step 2.4. Your values will differ from the example.

WARNING: These lines contain your model API key and your OpenShift token. Do not share them or commit them to Git.

Avoid these common mistakes when answering the prompts:

[cols="1,2,2",options="header"]
|===
| Prompt | Correct | Incorrect

| Namespace
| `user1`
| `openshift-terminal` or `redhat-ods-applications`

| Model ID
| `redhataigemma-4-e4b-it`
| `RedHatAI/gemma-4-E4B-it` (the display name)

| Model API base URL
| `.../redhataigemma-4-e4b-it/v1`
| `.../v1/chat/completions` or a `localhost` URL

| Model API key
| `sk-oai-****************`
| `Bearer sk-oai-****************`
|===

== Step 2.4: Create the `.env` File

The lab notebooks read their connection settings from a `.env` file at the root of the lab repository. The same file is used in Modules 2 to 5.

. In the same workbench terminal, still inside `rhoai-evalhub-lab`, open a new `.env` file:
+
[source,sh,role="execute"]
----
vi .env
----

. If the file already contains text, press `Esc` and type `ggdG` to clear it.
. Press `i` to enter insert mode.
. Paste the seven lines you copied in Step 2.1.
. Press `Esc`, type `:wq`, and press *Enter* to save and exit.

The notebooks load `.env` with `python-dotenv`, so you do not need to run `source .env`.

IMPORTANT: Keep `.env` in the `rhoai-evalhub-lab` directory, not in a notebook subdirectory. Each notebook loads `../.env` relative to its own folder.

== Step 2.5: Log In to OpenShift from the Workbench

Some setup cells run `oc` commands inside the workbench, for example to build the Korean MCQ evaluator image and to store your model API key as a Secret. By default, `oc` in the workbench runs as the workbench's own service account, which cannot create these resources. Log in as your user so that those cells succeed.

. In the workbench terminal, log in with the OpenShift token already saved in `.env`:
+
[source,sh,role="execute",subs="attributes+"]
----
oc login --server={openshift_api_url} \
  --token="$(grep EVALHUB_AUTH_TOKEN .env | cut -d"'" -f2)" \
  --insecure-skip-tls-verify=true
----

. Confirm that you are logged in as your user:
+
[source,sh,role="execute"]
----
oc whoami
----
+
The output must be your user name, such as `user1`. If it shows `system:serviceaccount:...`, the login did not succeed; rerun the previous command.

The notebooks share this login, so you do not need to restart the notebook kernel.

NOTE: Your OpenShift token expires after a period of time, typically about a day. If notebook calls later return HTTP `401`, rerun the setup script from Step 2.1, replace the contents of `.env`, repeat this step, and restart the notebook kernel.

== Key Concept: One Client for Every Evaluation

Every hands-on module uses the same EvalHub SDK client. It needs only the EvalHub URL, your OpenShift token, and your namespace, which EvalHub treats as your *tenant*:

[source,python,subs=none]
----
from evalhub import SyncEvalHubClient

client = SyncEvalHubClient(
    base_url=EVALHUB_URL,           # from .env
    auth_token=EVALHUB_AUTH_TOKEN,  # from .env
    insecure=True,                  # workshop clusters use self-signed certificates
    tenant=NAMESPACE,               # jobs and experiments are created in your namespace
)

providers = client.providers.list()
print(f"Available providers: {len(providers)}")
----

Each evaluation framework, such as GuideLLM or the Korean MCQ adapter, is a *provider* behind this client. In the next modules, you submit jobs to different providers with the same client and the same job request structure.
