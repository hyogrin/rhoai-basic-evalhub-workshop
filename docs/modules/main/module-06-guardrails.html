Guardrails Evaluation (Optional)

This module is an optional extension for participants who finish all required modules (Modules 1-5) early. Review the reference notebooks and example reports below if you have time and want to explore content safety. You can complete the workshop without running these notebooks.

The NeMo Guardrails evaluation with Kanana Safeguard or Nemotron Safety Guard requires additional model deployments and endpoint configuration. These steps are outside the workshop exercises; the notebooks are provided as references for further exploration.

What You Can Explore

Accuracy and performance do not answer “is this safe to serve?” The reference notebooks show how to evaluate content-safety guardrails on Korean hate-speech data using NeMo Guardrails with Kanana Safeguard 8B or Nemotron Safety Guard.

You can use these notebooks to:

  • Compare regex-only filtering with model-backed content safety.

  • Evaluate labeled K-MHaS samples and measure precision, recall, F1, and accuracy.

  • Inspect false positives (safe messages blocked) and false negatives (harmful messages allowed).

  • Compare category-level filtering results across safety models.

  • Generate HTML reports and record evaluation metrics and artifacts in MLflow.

  • Explore Korean prompt examples, category filtering, and layered guardrails in the advanced notebook.

Reference Notebooks

The notebooks are in rhoai-evalhub-lab/5_eval_guardrail/ in your Workbench. You can read them and review the example reports without deploying additional models.

  • 1_guardrail_setup.ipynb — NeMo Guardrails configuration reference: ConfigMaps for regex-only and model-backed content safety, registration with the NemoGuardrails resource, and connectivity checks.

  • 2_guardrail_test.ipynb — interactive comparison: Compare the responses from regex-only and content-safety configurations.

  • 3_evaluate_guardrail_nemo.ipynb — Nemotron Safety Guard evaluation: Evaluate K-MHaS samples through NeMo Guardrails and generate metrics and an HTML report.

  • 3_evaluate_guardrail_kanana.ipynb — Kanana Safeguard evaluation: Integrate Kanana with NeMo Guardrails using its prompt format and custom output parser, then evaluate Korean content safety.

  • 4_evaluate_guardrail_advanced.ipynb — further exploration: Examine prompt changes, category filtering, layered guardrails, and fine-tuning approaches using existing evaluation results.

If You Want to Run the Notebooks Later

Plan for additional GPU capacity to deploy the evaluation target LLM and your chosen guardrail model. You only need one safety model to explore a single evaluation path; comparing Kanana and Nemotron requires access to both models.

Before executing the reference notebooks:

  • Deploy the LLM used as the evaluation target and a safety model: Kanana Safeguard 8B or Nemotron Safety Guard.

  • Deploy the NeMo Guardrails service and configure it to use the target LLM and safety model endpoints.

  • Configure the model names, endpoint URLs, authentication, and guardrails route required by your chosen notebooks. The seven connection variables from Module 2 alone are not sufficient for this extension.

  • Arrange the cluster permissions needed to manage the guardrails configuration, and check model connectivity and MLflow access with your instructor or administrator.

Use the chosen notebook’s prerequisites and configuration cells as the reference for your environment. After the deployments and endpoint settings are ready, you can run the evaluation and generate reports like the examples below.

Example Report Outputs

The following reports come from saved evaluations of 2,000 K-MHaS samples in the companion lab. You can inspect them without running a notebook or adding GPUs. They illustrate the output format; results depend on the models, guardrail configuration, and dataset samples used.

Each evaluation produces:

  • A self-contained HTML report with summary metrics, charts, category breakdowns, and result analysis.

  • A CSV file containing per-sample evaluation results.

  • A confusion matrix and filter-rate chart to show correct decisions, over-blocking, and missed harmful content.

Generated files are saved under results/guardrail/ in the lab repository. The notebooks print the output paths and include cells for logging metrics and artifacts to MLflow.

How to Read the Reports

  • Precision: Of the blocked messages, how many were actually harmful?

  • Recall: Of the harmful messages, how many were blocked?

  • F1: How well does the configuration balance precision and recall?

  • False positive rate: How often are safe messages blocked?

  • False negative rate: How often does harmful content pass through?

Use the confusion matrix and category breakdown to identify where a configuration over-blocks or misses harmful content. Compare reports using the same dataset samples and evaluation settings before drawing conclusions about the models.
